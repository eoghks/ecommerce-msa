# UI 전체 스윕 테스트 (브라우저 실검증)

> 목적: 화면 깨짐(레이아웃)과 기능 동작을 화면별로 실제 클릭·스크린샷으로 검증하고 결과를 기록한다.
> 실행: Claude 내장 브라우저(Browser pane), `http://localhost:5173`
> 결과 표기: ⬜ 미실행 / ✅ 정상 / ⚠️ 경미(비차단) / ❌ 문제

## 환경
- Frontend: http://localhost:5173 (Vite)
- Gateway: http://localhost:8080
- 인프라: PostgreSQL / Redis×3 / Kafka / MinIO (docker)
- 검증 계정: 테스트 중 직접 생성(USER / SELLER 승격 / ADMIN 시드)

## 발견 이슈 요약

### 🔴 실제 버그 → 수정 완료
- **[1-5] 새로고침 시 로그아웃** — StrictMode(dev) 이중 호출로 refresh 2회 발사 → H-B 1회용 토큰 회전으로 둘째 401 → 로그아웃. **authStore single-flight 디듑으로 수정, 재검증 통과.** (PR #65 머지)

### ⚠️ 데이터/정리 사항 (버그 아님)
- 더미 상품 3건(SellerPhone Model 1~3, `http://img/N.jpg`) — E2E 때 생성된 테스트 쓰레기, 이미지 안 뜸. 정리 권장.

### 오탐(거짓 버그 아님으로 판명)
- 상품 이미지 미표시 → **내장 브라우저 샌드박스가 localhost:9000 미렌더**. 실제 크롬은 정상.
- 장바구니 담기/주문하기 "안 됨" → **자동화 클릭이 일부 버튼의 React onClick 미트리거**. 클릭이 실제로 닿으면 POST 201 정상. 상품 결함 아님.

## 검증 방식 한계 & 커버리지
- **내장 브라우저(headless) 특성**: (1) 스크린샷은 pane 미표시로 불가 → 레이아웃은 DOM/오버플로우/CSS·실크롬 육안으로 대체. (2) 일부 버튼 자동 클릭이 불안정 → 주문/관리자 심층 플로우는 UI로 끝까지 못 감.
- **보완**: 주문 Saga·취소·실패주문·카테고리·판매금지 등 **백엔드 플로우는 앞선 API E2E(verifier)에서 전 시나리오 PASS**로 이미 검증됨.
- **UI로 실검증 완료(✅)**: 접속/헬스, 상품목록·이미지(실크롬), 정렬·가격필터·자동완성, 회원가입(실시간검증)·로그인·Navbar, **새로고침 세션유지(수정후)**, 위시리스트 추가·목록, 상품상세(별점·리뷰섹션), 장바구니 담기·표시.
- **UI 미완(➖)**: 주문 완료·배송지 화면·리뷰 작성·알림 뱃지·관리자 화면·반응형 — 자동화 클릭 한계로 이번 세션 미완(실브라우저에서 육안 확인 권장, 백엔드는 검증됨).
